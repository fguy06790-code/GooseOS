# Validation

## Widget math migration checked on 2026-11-07

Resource-counter arithmetic, 8/16/24/32-bit PCM decoding, float-sample sanitization, and spectrum smoothing/decay now execute in `goose/widget_math.goose`. Native Win32 counter queries, WASAPI/COM lifetime management and float bit loading remain in the C++ adapter. Exports run on the desktop UI thread initialized by the existing entry point.

Six native tests and sixteen cross-suite checks passed locally. The widget-specific native host compares the generated Goose code with the prior arithmetic over 265,808 PCM samples (exhaustive 8/16-bit values, deterministic 24/32-bit samples and sign boundaries), invalid and extreme counters, NaN/infinity/signed zero, and 100 smoothing/decay updates. The native test is compiled with ASan/UBSan; the generated Goose runtime itself is not instrumented by the C++ sanitizer flag. The changed production widgets.cpp compiled to an amd64 object using real pinned D3DKMT headers. There is no new guest boot, hardware/audio capture trial, Windows 11 baseline or ISO validation for this change.

## Desktop layout migration checked on 2026-11-06

Desktop layout calculations now run in Goose, including DPI scaling/rounding, animated launcher position, task buttons, app rows, search edit, and widget placement. A native differential harness compares the original C++ layout with Goose across 468 screen/task/motion/widget configurations. Five native checks and fifteen cross-suite checks pass locally. Native desktop tests initialize Goose before invoking migrated layout code.

The first GitHub Windows run exposed a test executable without its Common Controls v6 manifest (loader exit 0xc0000139). The Store test now embeds the same manifest as the application, rather than relying on Wine's broader default exports. This affects the host test build; the production Store already carries that manifest.

## Goose language port checked on 2026-11-06

The Goose v2026.3 compiler (runtime `4d3da949e563`) generated the production library from `goose/core.goose`. Four native Linux tests passed, with AddressSanitizer/UndefinedBehaviorSanitizer enabled for native C++ test code. The amd64 cross suite passed all 14 checks: 12 Windows binaries under Wine 10 and two Goose-source tests using the Linux host compiler. This includes actual generated C export calls and the existing Store/launcher/setup/WLAN regressions. The spectrum export matched the original C++ exactly across 33,792 band comparisons (96 stereo profiles and 11 rates, including zero and UINT32_MAX).

The changed desktop widgets source passed MinGW syntax compilation using real pinned D3DKMT headers; warnings came from the existing SDK definitions. The CMake library rejects non-64-bit targets and a mismatched Goose runtime. Official Linux and Windows compiler archives were verified by SHA-256; Linux bootstrap execution and repeated cached install passed. Source staging was checked for idempotency. Actionlint, Python/shell syntax checks and whitespace checks passed.

This is a partial application-language migration. Native Win32 capture, GUI callbacks, setup, kernel and drivers are not converted to Goose. No complete OS link, new ISO, guest boot, physical Wi-Fi test or Windows 11 baseline was performed for the language port. Earlier native validation below does not establish those results.

## Source fixes checked on 2026-11-06

The isolated CMake suite compiled with amd64 MinGW GCC 14 and passed all 11 tests under Wine 10 with Xvfb. It covers retry policy, hardware-ID matching, WLAN startup/pending transitions, WLAN session errors and cleanup, network setup ordering, launcher navigation, window policies, Store interaction/restart reporting, and setup download/hash/INF failures. External jobs, installers, WLAN operations, audio sampling and icon rendering are mocked where appropriate; no host drivers or Wi-Fi profiles were changed.

Tests built against the original code reproduced the pending-start failure, Store installation during catalog loading, unbounded no-progress downloads, acceptance of partial-file hashes after a read failure, and stale component metadata. The changed functions pass those regressions. A single-request scan-buffer policy also fails the new overflow regression; the production resizing helper passes it.

The portable NWIFI scan-buffer test passed with `-Wall -Wextra -Werror` and AddressSanitizer/UndefinedBehaviorSanitizer. It checks allocation growth using the reported total BytesNeeded, retry/allocation limits, malformed result lengths and cleanup. Its simulated status/type definitions exercise the algorithm, not Windows ABI parity. The actual changed NWIFI msm.c and protocol.c also compiled to amd64 objects against real pinned LiberNT headers, including headers generated by the pinned SDK generator. The changed Store CLI compiled, and Settings passed syntax compilation with a test compatibility header for MinGW SDK macros.

The new GitHub workflow runs the portable test on Linux and the isolated suite on a hosted Windows runner, then gates the ISO build on both jobs. That workflow has been added locally but has not been run on GitHub. The hosted Windows runner is not a Windows 11 reference baseline.

Actionlint and `git diff --check` passed. Cppcheck's compile-database analysis was limited by MinGW header preprocessing; a compiler-preprocessed setup check reported SDK/intrinsic constructs and a mock-return portability warning. Inspection did not establish an additional defect in the changed production code. This is limited static analysis, not an exhaustive clean result.

No new ISO, full driver link, guest boot, Windows 11 baseline, i386/arm64 OS build, or physical-hardware test was performed for this patch. The ASUS zero-network trial is not established as fixed by buffer growth. Chrome's blank window, real Wi-Fi scanning/connection, live audio and broader application/hardware compatibility remain unresolved. Earlier results below describe previous builds and do not validate these source changes. The Store is now included in the published v1.1.0 release; older development-build statements below are historical.
